THE CLOSEST-PAIR PROBLEM

Divide the plane. Find the neighbors.

Brute force computes the Euclidean distance for every pair. Divide-and-conquer sorts by x, recursively solves two halves, merges their y-sorted points, then checks neighbors in the strip around the dividing line.

The strip extends d on either side of the split: its width is 2d. Here d is the smaller distance returned by the two halves at the start of that merge. The algorithm only needs to compare the next seven points in y order, stopping sooner when their y separation exceeds the current best distance.

Play shows real recursive splits, base-case comparisons, strips, and merges. Faded points are outside the current subproblem. The final pair from each algorithm has its own color. If they coincide, a thick orange line and a thinner dashed blue line show both.

Corner cases: duplicate points have distance 0; N = 2 has one pair; N < 2 has no defined closest pair. Shared x/y coordinates and collinear sets are supported. Different pairs may tie for the same minimum distance.

Performance tests use the same input for both algorithms, alternate their execution order across repeats, and report medians. Generation, validation, animation, and network time are excluded. Every run checks that minimum distances agree. Timings vary by machine and workload.
