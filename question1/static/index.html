THE WAY THROUGH

A maze with a memory.

Move up, down, left, or right. Each move costs one step. Entering a key cell collects its key; a door is passable only when you already hold the matching key.

Build, solve, explore

  1. Enter a square grid, upload a CSV, or generate a maze. Set T to the number of distinct key/door types present.
  2. Choose an algorithm and select Visualize search. Watch branches expand, waiting cells appear, and walls or locked doors reject moves. DFS also visibly backtracks. A step count or -1 is revealed when the search finishes.
  3. The search plays first, followed by the resulting route. Pause, step in either direction, or drag the timeline. Use Jump to route to skip exploration. Each search state has its own keys: switching branches may change the displayed inventory. Keys are never lost within a route.
  4. Download the path CSV. Open cells on the route become x; special cells become x(a), x(A), x(S), and so on. Exported CSVs can be imported again.

Four ways to search

BFS explores by distance. DFS follows a branch deeply, then backtracks; its first route is not necessarily shortest. Dijkstra explores by total cost; because each move costs one, its order matches BFS with the same tie-breaking. A* combines distance traveled with Manhattan distance to the exit. BFS, Dijkstra, and A* guarantee a shortest route.

All four track position and key inventory. The animation shows actual search decisions and stops when the exit is found or the reachable states are exhausted. The active branch is a candidate route, not one traveler teleporting between cells. Neighbor labels explain each move check; waiting cells may contain multiple inventory states.

About E: The problem uses E for both the exit and door e. Here E always means exit; enter door e as D:e in comma- or space-separated rows. Each key/door pair has a unique color, with labels to distinguish them. Keys show a key icon; doors show a lock.

Manual grids support 2–25 rows. Generated mazes use odd sizes from 7–25 and place all T pairs along a solvable route. Missing or inaccessible keys can make a manually entered maze unsolvable.
