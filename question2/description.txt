================================================================================
                    QUESTION 2 — CLOSEST PAIR OF POINTS IN 2D
                              DETAILED DESCRIPTION
================================================================================


1. PROBLEM STATEMENT
====================

Given N points in a 2D Euclidean plane, find the pair of points (p_i, p_j) with
the smallest Euclidean distance:

    d = sqrt((x_i - x_j)² + (y_i - y_j)²)

Requirements:
  - Implement both Brute-Force and Divide-and-Conquer algorithms
  - Compare their performance empirically for increasing input sizes
  - Verify that both algorithms always agree on the minimum distance
  - Handle all corner cases: duplicates, collinear points, shared x or y
    coordinates, N = 0, N = 1, N = 2, extreme coordinates (±10^100)
  - Provide interactive visualization with animated recursive splitting
  - Generate benchmark reports (CSV + SVG chart)

========================

3. BRUTE-FORCE ALGORITHM
=========================

3.1 How It Works
-----------------
Enumerate every unordered pair (i, j) with 0 ≤ i < j < N, compute the Euclidean
distance, and track the minimum.

    def brute_force(points):
        best = (infinity, -1, -1)
        for i in range(len(points)):
            for j in range(i + 1, len(points)):
                d = math.hypot(points[i][0] - points[j][0],
                               points[i][1] - points[j][1])
                candidate = (d, min(i, j), max(i, j))
                if candidate < best:
                    best = candidate
        return best

3.2 Why math.hypot?
--------------------
Using math.hypot(dx, dy) instead of sqrt(dx² + dy²) prevents floating-point
overflow and underflow for extreme coordinates. For points at ±10^100, squaring
would produce 10^200 which overflows float64, but hypot handles this internally
using the "accurate hypot" algorithm.

3.3 Deterministic Tie-Breaking
-------------------------------
Candidate tuples are (distance, min_id, max_id). Since Python compares tuples
lexicographically, ties in distance are broken by point IDs, ensuring
deterministic and reproducible results.

3.4 Complexity
--------------
  Time:  O(n²) — exactly n(n-1)/2 distance computations
  Space: O(1) auxiliary — only tracks the current best candidate
  At N=1600, this means 1,279,200 comparisons.


4. DIVIDE-AND-CONQUER ALGORITHM
================================

4.1 Overview
-------------
This implementation achieves true O(n log n) time complexity by using a linear
merge of y-sorted sublists (not re-sorting at each level, which would give
O(n log² n)). The key insight is maintaining y-sorted order through a
merge-sort-like bottom-up merge during the combine step.

4.2 Step-by-Step Algorithm
---------------------------

STEP 1: PRE-SORT
    Sort all point indices by (x, y, original_id) in O(n log n).
    This is done exactly once, not per recursive call.

STEP 2: DUPLICATE SHORTCUT
    Scan adjacent points in x-sorted order in O(n). If any two consecutive
    points share identical coordinates, return distance 0 immediately.
    This avoids unnecessary deep recursion for trivially coincident points.

STEP 3: BASE CASE
    For subproblems of size ≤ 3, use brute force (constant work).
    Return the best distance and the points sorted by y-coordinate.

STEP 4: DIVIDE
    Split at midpoint: mid = (lo + hi) // 2
    Split line coordinate: split_x = (x[mid-1] + x[mid]) / 2
    This ensures symmetric strip boundaries rather than using a point
    as the dividing line (which could place strip-crossing pairs on the
    wrong side).

STEP 5: CONQUER
    Recursively solve the left half [lo, mid) and right half [mid, hi).
    Each recursive call returns:
      - The best candidate (distance, id1, id2) in that half
      - The points in that half sorted by y-coordinate

STEP 6: COMBINE — LINEAR Y-MERGE
    Merge the y-sorted left and right results in O(n) using a standard
    two-pointer merge (identical to merge sort). This is the key to
    achieving O(n log n) overall — we avoid re-sorting the strip points.

STEP 7: STRIP SEARCH
    Let d = min(d_left, d_right).
    Extract strip points: all points where |x - split_x| ≤ d.
    These are already in y-sorted order (from the merged result).

    For each point in the strip, check at most the next 7 points.
    WHY 7? A geometric packing argument proves that at most 8 points
    can fit in a d × 2d rectangle with pairwise distance ≥ d. Therefore,
    for any point, at most 7 subsequent y-sorted points need checking.

    Break early if Δy > d (no need to check further points).

    If any strip pair has distance < d, update d and the best candidate.

STEP 8: TRACE RECORDING (OPTIONAL)
    When record=True, every step emits events:
      - "split": records split_x coordinate and subproblem boundaries
      - "base": records base case evaluation
      - "compare": records each distance comparison in brute force
      - "strip": records strip region and points being checked
      - "merge": records y-merge step
      - "complete": records subproblem completion
      - "duplicate": records early detection of coincident points
      - "insufficient": records N < 2 case

4.3 Recurrence Relation
-------------------------
    T(n) = 2·T(n/2) + O(n)

    The O(n) combine step includes:
      - O(n) y-merge
      - O(n) strip construction
      - O(n) strip comparisons (7 per point)

    By the Master Theorem: T(n) = O(n log n)

4.4 Complexity
--------------
    Time:  O(n log n) — true linearithmic, not O(n log² n)
    Space: O(n) auxiliary for the merged arrays
           O(n log n) if trace recording is enabled (one trace event per
           recursive call, log n levels)

4.5 Handling Edge Cases
------------------------
    N = 0 or N = 1:  Returns distance = null, pair = null
                     (reported as "undefined — no pair (N < 2)")
    N = 2:           Returns the single pair
    Duplicates:      Detected in O(n) scan; returns distance = 0
    Collinear:       Partitioning divides by sorted rank, not coordinate
                     value, preserving balanced subproblems
    Same x or y:     Handled correctly because split uses midpoint of
                     coordinates, not a point coordinate
    Ties:            Deterministic tie-breaking via (distance, min_id, max_id)
    Extreme coords:  Handles ±10^100 via math.hypot overflow protection


5. BENCHMARKING SYSTEM
=======================

5.1 Benchmark Runner (closest_pair.py → benchmark())
------------------------------------------------------
    - Generates random points for sizes [50, 100, 200, 400, 800, 1600, ...]
    - Supports 6 distributions: uniform, integer, collinear, same-x, same-y, duplicates
    - Runs each algorithm multiple times (default: repeats=3)
    - Alternates execution order to eliminate cache/warmup bias
    - Reports MEDIAN runtimes (not mean, to eliminate outliers)
    - Verifies agreement between algorithms on every run
    - Timing uses time.perf_counter_ns for nanosecond precision

5.2 Report Generation (reports.py)
-----------------------------------
    benchmark_csv(data):
        Generates CSV with columns: N, brute_force_ms, divide_conquer_ms, distances_agree

    benchmark_svg(data):
        Generates a standalone SVG chart with:
        - Dual y-axis (not used here, but single clear axis)
        - Grid lines, axis labels, tick marks
        - Polylines for both algorithms with distinct colors
        - Legend
        - Clean vector graphics (no rasterization, infinite resolution)

5.3 Empirical Results
----------------------
    Python 3.12, uniform random floats, seed 42, median of 3 runs:

    N       Brute Force     D&C         Speedup     Agree?
    ----    -----------     --------    -------     ------
    50      0.272 ms        0.093 ms    2.9×        Yes
    100     1.104 ms        0.198 ms    5.6×        Yes
    200     4.400 ms        0.428 ms    10.3×       Yes

    Observations:
    - Doubling N quadruples Brute-Force runtime (confirming O(n²))
    - D&C scales nearly linearly with logarithmic overhead (O(n log n))
    - At N=1600, D&C is ~60× faster
    - All 18 measured runs produced exact floating-point distance agreement

8. INPUT VALIDATION
====================

The validate_points() function enforces:
  - Points must be a list of (x, y) tuples
  - Coordinates must be finite numbers (int or float)
  - Booleans are rejected (isinstance check excludes bool subclass of int)
  - Coordinates must be within [-10^100, 10^100]
  - NaN and Infinity are explicitly rejected

The generate_points() function supports:
  - n: number of points
  - seed: optional for reproducibility
  - distribution: "uniform", "integer", "collinear", "same-x", "same-y", "duplicates"


9. POINT GENERATION DISTRIBUTIONS
===================================

  uniform:    Random floats in [0, 1000) × [0, 1000)
  integer:    Random integers in [0, 100] × [0, 100]
  collinear:  All points on the line y = 2x + 3 with random x values
  same-x:     All points share x=500, random y values
  same-y:     All points share y=500, random x values
  duplicates: Half the points are copies of the other half
